Discord Issue Bot — Oracle Cloud Deploy Guide

Host the bot 24/7 for $0 on Oracle Cloud's Always Free tier. It keeps every command — all 5 slash commands and the !issue / !ability text commands — because it runs as a real always-on Linux process, not a serverless function.

$0 forever Needs a card for signup verification only (no charge) ~30 minutes
1

Create the Oracle Cloud account

  • Go to signup.cloud.oracle.com and click Start for free.
  • Use a real email and phone number — Oracle's fraud checks are strict, and new accounts sometimes go through a manual review (usually a few hours, sometimes a day).
  • Enter a credit/debit card when asked. It's used for verification only — a temporary authorization hold, nothing is charged.
  • Pick your home region carefully — it can't be changed after signup. Any region with Ampere capacity works for this bot.
⚠️ Do not click "Upgrade to Pay As You Go" — that's optional and removes the $0 guarantee (you'd be billed if you exceed free limits). The free tier is enough for this bot.
📌 See Oracle's official Always Free resources doc for the exact allowances (currently 2 OCPU / 12 GB compute + 200 GB storage).

2

Create the VM (instance)

  • Open the Oracle Cloud Console → menu → Compute → Instances → Create instance.
  • Name: bd-discord-bot (anything).
  • Image: Ubuntu 24.04 (login user will be ubuntu).
  • Shape: Ampere (A1 Flex) — pick 1 OCPU / 6 GB RAM. See the shape docs if you want to browse options.
  • Boot volume: 50 GB (fits inside the 200 GB free allowance).
  • SSH keys: generate a new key pair and download the private key now (or paste your existing public key). You'll need it to log in.
  • Click Create. If you get "out of host capacity", retry in a different availability domain or drop to a smaller shape — it usually succeeds on a second try.

Open Oracle Cloud Console → Oracle docs: creating an instance →

3

SSH into the VM

The bot only makes outbound connections (Discord + GitHub), so no inbound ports are needed besides SSH (port 22, already open by default). Open a terminal on your machine and run:

ssh -i ~/.ssh/oci_key ubuntu@<PUBLIC_IP>
📌 Replace <PUBLIC_IP> with the IP shown on your instance page. On Ubuntu images the user is ubuntu; on Oracle Linux it's opc. See Oracle's SSH docs if you're on Windows.
4

Run the one-shot bootstrap

Inside the VM, clone the repo and run the bootstrap script. It installs Node 20 + pm2, asks you for the env values (secrets typed invisibly), starts the bot, makes it survive reboots, and installs the Oracle idle-keepalive task.

git clone -b feat/discord-issue-bot-v2 https://github.com/4-mat/bd-autohost-bot-new.git
cd bd-autohost-bot-new/discord-issue-bot
bash deploy/oci-bootstrap.sh

5

Verify it's online

Check the bot is running and connected to Discord:

pm2 status
pm2 logs bd-discord-issue-bot

You should see [bot] logged in as ... followed by the command registration line. Then test /bug, /map, /ability, and !issue in your server.

  • Account created (free tier, card only verified)
  • VM created — Ubuntu 24.04, Ampere 1 OCPU / 6 GB, 50 GB disk
  • SSH login works
  • Bootstrap ran and env values filled in
  • Log shows the bot logged in
  • Commands work in Discord
6

Keeping it alive (updates & gotchas)

  • Update the bot:
cd ~/bd-autohost-bot-new
git pull
cd discord-issue-bot
npm install
pm2 restart bd-discord-issue-bot
  • Cost check: this should stay at exactly $0. Verify under Billing → Usage — the instance fits inside the free allowances.
  • Idle reclamation: Oracle reserves the right to reclaim Always Free instances that sit below 20% CPU/network/memory (95th percentile) for 7 days. A quiet bot can look idle, so the bootstrap installs oci-keepalive.sh (10 min of low-priority activity every 2 hours) as insurance — it never affects the bot (nice -n 19). Remove it anytime with crontab -e; Oracle emails you before any termination regardless.
  • Commands missing in Discord? Re-register: cd ~/bd-autohost-bot-new/discord-issue-bot && npm run register — and make sure Message Content is enabled in the Developer Portal (Bot → Privileged Gateway Intents), or the ! text commands can't see messages.
  • pm2 crashed/stopped after reboot? Re-run pm2 save and sudo env PATH="$PATH:/usr/bin" pm2 startup systemd -u ubuntu --hp /home/ubuntu.
